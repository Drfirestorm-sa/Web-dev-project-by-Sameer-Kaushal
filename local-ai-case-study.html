Exploring a local assistant across two personal computers

I have been setting up a local AI assistant that separates the gateway from the machine running the language model. The work has focused on connecting the components, understanding model requirements and testing what the available hardware can support.

LM StudioQwen3.5-4BOpenClawHermesTailscale
2-device
Recorded setup: a Windows gateway PC and an ASUS V16 laptop for local inference.

My contribution

  • Set up LM Studio to serve the Qwen3.5-4B model on the ASUS V16 laptop.
  • Used an older Windows 11 PC as the OpenClaw gateway host.
  • Worked on connecting the two machines over Tailscale and integrating the Hermes agent.
  • Investigated context-window requirements, local inference speed and possible voice-input components.

Technologies and setup

A challenge I addressed

The Hermes agent reported that the model's initial 8,192-token context window was below its stated 64,000-token minimum. I later set the LM Studio context to 64,000 tokens to meet that requirement.

This did not solve a separate limitation: local inference was still slow. It taught me to distinguish configuration compatibility from performance.

Current status and learning

The gateway, local model serving and device connectivity have been part of the recorded setup. Faster-Whisper and Pipecat have been explored for voice interaction, but a complete, repeatable voice pipeline is not yet evidenced as finished.

This work has developed my understanding of local model deployment, networked components, integration constraints and practical performance trade-offs.
